## 0. 현황 (조사 2026-11-01)

- 측정 하네스(`crates/loom-bench`)에는 DOM 정합성 장치가 **없다**. 트랙 L은 `start()` 한 번으로 캠페인 전체가 돌고, 조작 단위 DOM readback·검증 모드가 없다.
  내보내기는 `start`, `TrackTCell`, `CatchUpCell`뿐이다. `observe_mutations`는 M2 교차검증용 개수 집계만 한다.
- 후보 조립(`make_k/c/d/d_lis/e/e_lis`, lib.rs 963-1090)은 `CountingDom<BrowserDom>`·`web_sys`에 묶여 있어 네이티브에서 그대로 돌릴 수 없다.
- 흩어진 정합성 자산: `loom-runtime/tests/list_candidates.rs`(MockDom 손 시나리오, 6후보), `tests/k_dispatch.rs`(순수 함수 + 분기 DOM 효과),
  `tests/cond_candidates.rs`(B·F·F-i·F-iii), `loom-track-n`(RecordingDom + 참조 모델, 중첩, C=위치 귀속, 컴파일러 생성 arm).
  **측정에 쓰이는 조립·워크로드·시드 그대로**를 조작마다 검사하는 장치는 어디에도 없다.

## 1. 방식 — 측정 하네스 안의 기능 플래그 모듈 (`--features g1`)

- `crates/loom-bench/src/g1.rs`를 `#[cfg(feature = "g1")] mod g1;`로 **lib.rs 맨 끝**에 붙인다(앞쪽 줄 번호를 밀지 않으므로 panic 위치 문자열이 안 바뀐다).
  하위 모듈이라 비공개인 `make_*`·`RowShape`·`Workload::apply`·`derive_seed`·`build_cell`을 **그대로** 호출한다 — 측정과 같은 조립·같은 시드 열을 검사한다.
- **동결 산출물 불변 확인(2026-11-01 실측)**: `[features] g1 = []` 선언 + 끝줄 모듈 선언을 넣고 기능을 끈 채 `tools/build-frozen-bench.sh`로 빌드 → wasm
  `b509135f…`·js `994d2cb1…`로 **동결본과 같았다**. 실제 G1 코드를 넣은 뒤에도 같은 확인을 다시 한다(존재 단언: g1 빌드에는 `g1_*` 내보내기가 있다).
- G1 산출물은 측정 산출물과 **다른 빌드**다(추가 모듈). 검사 대상 함수의 소스는 같지만 바이트는 같지 않다 — 기록에 그대로 쓴다.
  두 벌을 만든다: **release**(측정과 같은 최적화) + **dev**(`debug_assert` — 키 누락, 선택 사전조건, `KEY_COLLISIONS` 계수기 — 가 살아 있음).
- 실행: Playwright로 페이지(`demo/g1.html`, 신설)를 띄워 `g1_run(…)`을 부르고 JSON 결과를 받는다. **Chromium(1차), Firefox**(판정 경로 = 네이티브
  moveBefore), **WebKit**(실폴백 경로 — §9 E-1에 따라 제약 보고용, 컨테이너), Chromium **폴백 강제**(진단용).
- 성능을 재지 않는다(시간 값 미기록). 측정 데이터가 아니므로 수집 지시 대상이 아니라고 본다 — **확인 요청 1**.

## 2. 트랙 L 검사 (조작마다)

각 셀 = (후보, 워크로드, Item ∈ {ItemId, String}, 행 모양 ∈ {R1, R2, R3}, write 변형 ∈ {조건부, 무조건(C·D·D-LIS)}, n ∈ {100, 1000}).
시퀀스: 측정 시드 대역(`derive_seed("measure", …)`)으로 **측정과 같은 대상 열** 20 rep + G1 전용 대역(`"g1"`)으로 독립 시드 20 rep, 그리고
상태 누적 결함을 잡기 위해 rep을 **복원 없이 이어 붙인 연쇄** 1개(W6 stress 포함). n=10,000은 연쇄 1개만(시간 제약).

1. **내용(순서 포함)**: 조작 뒤 루트 `<ul>`의 행 열이 **같은 후보를 목표 리스트로 새로 마운트한 결과**와 노드 구조·텍스트·속성까지 같다
   (`outerHTML` 비교 — 손으로 쓴 렌더 모형 대신 후보 자신의 초기 렌더를 신탁으로 쓴다). 독립 닻: 각 행의 텍스트에 `item.to_string()`이 순서대로 나온다.
2. **정체성(후보 자신의 명세 의미론 — §3.5 "C를 keyed로 판정 금지")**: 조작 전에 행 노드마다 JS 표식을 붙이고 조작 뒤 대조한다.
   - D·D-LIS·E·E-LIS(keyed, Retained): 양쪽에 있는 아이템의 노드는 **같은 객체**, 새 아이템은 **처음 보는** 노드.
   - C(위치 귀속, Slots): 인덱스 `i < min(old,new)`의 노드는 같은 객체(내용만 갱신), 늘어난 자리는 새 노드.
   - K(§10): `k_dispatch(old,new)`로 분기를 계산해 — NoOp: 전부 같은 객체 / Append: prefix 같음 + 꼬리 새 노드 / Truncate: 남은 prefix 같음 /
     Clear: 행 0 / Full: 전부 새 노드. 그리고 **발동 수 집계**.
3. **고아 없음**: 루트 아래 행 수 = 리스트 길이, 컨테이너 밖으로 샌 노드 없음, 페이지 오류 0.
4. **E 전용**: 조작 뒤 World의 `OrderKey` 순서 = DOM 순서(트랙 N lib.rs:~335 검사 이식). 반례 `[A,B,C]→[B,C,A]` 명시 케이스. 무작위 순열은 W2/W3 시드가 덮는다.
   조문의 "이동 집합 OrderKey 내림차순 정렬 적용"은 구현에서 별도 단계가 아니라 `plan_from_selection`의 오른쪽→왼쪽 배치(Verus 검증)가 맡는다 —
   G1 기록에 이 대응을 문언 대조로 적는다(DOM 결과 검사가 기계 확인, 대응 진술은 서술).
5. **K 분기 발동**: 측정 워크로드만으로는 NoOp·Truncate가 **발동하지 않는다**(전 워크로드가 값을 바꾸고, 꼬리 제거 워크로드가 없다).
   G1 전용 시퀀스(같은 리스트 재대입, 꼬리 k개 제거)를 더해 다섯 분기 각각 ≥1 발동을 단언한다.
6. **key_hash**: 조문은 "충돌은 디버그 빌드 assert"인데 구현은 개정 #12 (ii)-5로 **계수기 `KEY_COLLISIONS` + 검증 경로**로 바뀌었다. G1 기록에 이 문언 차이를
   명시하고, dev 빌드에서 계수기 값과 `g0r1_select.rs` 충돌 사슬 테스트(D·D-LIS·E·E-LIS) 통과를 함께 기록한다.

## 3. 트랙 T 검사 (스텝마다)

각 arm(B, F, F-i, F-ii, F-iii, lazy) × 구성(flat, chain3) × 크기 {100, 1000}을 `build_cell`로 조립해 토글·값 변경 스텝을 진행하며 검사한다.
- 조건 참: 서브트리가 붙어 있고 보이며 내용 = 현재 값(같은 상태의 새 마운트와 비교).
- 조건 거짓: B = 없음 / F(CSS 은닉) = 있으나 숨김, **은닉 중에도 값이 계속 패치됨**(자기 명세) / F-i·F-ii·F-iii = 분리됨 / lazy = 첫 참 전에는 미생성.
- 재부착 catch-up: 거짓 동안 값을 바꾼 뒤 참으로 → 내용 = 현재 값(F-i·F-ii·F-iii·lazy; 지금 테스트는 쓰기 수만 본다).
- truthiness 에지: 참→참 대입은 DOM write 0(M2 카운트) + 노드 정체성 유지. 값 채널 `{user && <p>{user.name}</p>}` 갱신은 측정 셀 구성에 없으므로
  `loom-runtime` 네이티브 테스트(MockDom)로 B-보강 회귀 테스트를 신설한다.
- stale LRef 재현 테스트: **기각 조건 아님**(§4.3) — 재현 여부와 내용을 기록만 한다(RQ1 B-보강 갱신 재료).

## 4. 통과 기준(등재 후보)과 비공허 단언

- 통과: 판정 경로(Chromium·Firefox 네이티브)에서 **release·dev 두 빌드 모두** 위 1–5 및 트랙 T 검사 불일치 0건, dev 빌드 assert 발화 0건.
- WebKit·폴백 강제: 결과를 기록하고, 불일치가 있으면 **E의 채택 시 조건부 제약**으로 보고한다(기각 아님, §9 E-1). 그 외 후보는 폴백 경로가 없으므로 같은 결과여야 한다.
- 비공허(분석이 먼저 단언): 셀마다 검사한 조작 수 > 0 · 정체성 검사에서 "같은 객체" 판정 수 > 0 **이고** "새 노드" 판정 수 > 0(keyed 셔플 셀은 retain > 0) ·
  K 다섯 분기 각각 ≥ 1 · E 셀에서 실제 이동이 있었던 조작 수 > 0 · 트랙 T arm마다 참→거짓·거짓→참·참→참·거짓 중 값 변경 각각 ≥ 1 ·
  **음성 대조**: 의도적으로 틀린 기대(예: C를 keyed 의미론으로 검사)를 한 셀에 걸어 실제로 불일치가 잡히는지 확인(검사기가 무엇이든 통과시키지 않는다).
- 원장: `research-questions/data/rq1-g1-<날짜>-<브라우저>-<release|dev>.json`(G1 산출물 sha256, 소스 커밋, 셀별 검사 수·불일치·발동 수).

## 5. 탈락 시

G1 탈락은 §9 서두대로 **자격/정합성에 의한 탈락**으로 기록한다. 다만 프로토콜에는 G1 수리 절차가 없다(G2는 §5 수리 사이클이 있다).
제안: 구현 결함이면 §11-1 (i) "명세 준수 수리"(C 수리 전례)로 고치고 → 재동결(P2·최종, A/A가 걸리면 P1도) → 해당 후보 G0 확인 → G1 재실행. **확인 요청 3**.

## 6. 확인 요청

1. G1 실행(시간 미기록 정합성 검사)은 "데이터 수집 지시" 대상이 아니라고 보고 바로 실행해도 되는가.
2. 방식 1(측정 하네스 안 기능 플래그 모듈 — 측정 산출물 바이트 불변을 매번 확인)에 동의하는가. 대안은 (a) 하네스를 `DomOps` 제네릭으로 고치고 네이티브 검사
   (재동결 필요), (b) 별도 크레이트로 조립을 복제(측정과 다른 조립을 검사할 위험).
3. G1 탈락 시 수리 경로(5절).
4. 셀 범위: n ∈ {100, 1000} 전수 + 10,000은 연쇄 1개, rep 20+20. 늘리거나 줄일 것.
